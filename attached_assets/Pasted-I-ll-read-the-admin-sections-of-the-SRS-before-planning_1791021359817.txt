## What the SRS says Admin gets
Admin is the top role for now, since Super Admin is deferred. The SRS gives Admin everything Manager and Staff have, plus:
- **Team control (FR-37):** add, edit and deactivate staff and managers.
- **Products (FR-37):** edit loan types, rates, amounts, tenures, fees and required documents, and switch products on or off.
- **Audit log:** see who did what.

The Admin panel also needs the shared lead tools from FR-27 to FR-40: dashboard, leads, assignment, status workflow, enquiries, monitoring and reports.

## Design
- **Layout:** a desktop sidebar that collapses into a slide-out menu on phones. Tables turn into cards below 768px.
- **Status colours and the status flow:** one colour per status. The status flow comes from section 4: normal path, Rejected and Closed from any open status, only Admin and Manager can reopen, and a mandatory reason for Rejected and Closed.
- **Charts:** simple, dependency-free bar and line charts.
- **Demo behaviour:** everything works in memory with about 40 fake leads and nothing is saved. Every screen says it's sample data, like the customer side.
- **Safety:** no real data, and an "Admin demo" badge on every screen.

## Code structure
- `src/admin/` for the admin code and `src/admin/data.ts` for the sample data and the status rules.
- One file per screen.
- `App.tsx` just gets the `/admin/*` routes. The customer pages stay as they are.
